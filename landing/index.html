Why another panel?

Hosting a network shouldn't feel like babysitting.

One flaky plugin, one forgotten backup, one accidental rm -rf — and the whole night is gone. Carbon Panel treats your worlds the way production teams treat state: isolated, observable, and recoverable.

The usual way

Hand-rolled scripts and bare JVM processes on a shared host.

  • One bad mod corrupts every world sharing the host
  • Port-forwarding a new server means editing firewall rules
  • Backups are a cron job nobody has ever restored from
  • Idle servers burn RAM all night, every night

The Carbon way

Every server is a Docker container with real limits, routes and history.

  • Blast radius is one container, never the host
  • New server = new hostname, routed automatically
  • World-aware backups with retention and offsite copies
  • Deep-sleep to zero RAM, wakes when a player connects
Everything in the box

A control plane, not a start button.

Up in three steps

From clone to players in minutes.

No cloud account, no license key, no control plane phoning home. Just Docker and a browser.

1

Install the panel

Clone the repo and bring the stack up with Docker Compose. SQLite and the proxy are configured out of the box.

$ docker compose up -d
2

Create a server

Pick a loader and version, set CPU/RAM limits and JVM flags. Carbon provisions the container and its data volume.

› survival-01 · Paper 1.21 · 6 GB
3

Point players at it

Set a wildcard DNS record once. Every new server becomes a hostname — routed automatically on the single ingress port.

› survival.mc.yourdomain.com
Isolation & security

Trust it with your worlds.

Every player connection crosses a checked boundary before it reaches a container — and every container is fenced from the rest of your cluster.

  • Handshake-aware ingress

    Routes resolve from the Minecraft handshake itself, with per-IP rate limiting.

  • Container isolation

    Resource limits, mounted data volumes, no host dependency sprawl.

  • Fail-closed access

    Casbin-backed RBAC, OIDC SSO, JWT sessions and a recovery key for offline admin.

Questions

Good to know.

Is Carbon Panel really free?
Yes. It's open source under the MIT + MPL-2.0 licenses — free to use, modify and self-host. There are no paid tiers, no seats, and no cloud account required.
Where are my worlds and data stored?
In plain directories and Docker volumes on your own storage — including an SQLite control database and per-server data volumes. Nothing leaves your machine unless you configure offsite backups to S3-compatible storage.
Which server types and loaders are supported?
Vanilla, Paper, Purpur, Spigot, Bukkit, Fabric, Quilt, Forge, NeoForge, Folia and Pufferfish for Java Edition, plus Bedrock support through built-in Geyser/Floodgate modules. Java runtimes (8, 11, 17, 21+) are selected automatically.
Do I need to port-forward every server?
No. Carbon Panel's built-in proxy multiplexes traffic through a single port (25565) and routes players by hostname — so survival.yourdomain.com and creative.yourdomain.com can reach different containers with one DNS setup.
Can I run it alongside other Docker workloads?
Yes. Carbon Panel orchestrates its own isolated server containers and can manage remote Docker nodes too. Because each server is fenced in its own container, it won't collide with your other services.
How do I get started?
Clone the repository and run it with Docker Compose, or build from source with Go and Bun. The getting-started guide walks through Docker Compose, Proxmox LXC, prebuilt binaries and source builds.

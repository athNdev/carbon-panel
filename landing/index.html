04 / SLEEP & WAKE

Let it sleep.
Join to wake it.

Choose how an empty server rests. Native pause stops ticking on supported versions. Freeze suspends the process in memory. Deep sleep stops it to release JVM memory, then a player connection starts it again.

Product concept · example data · interface in development

Hosting servers shouldn't feel like babysitting.

One flaky plugin, one forgotten backup, one accidental rm -rf — and the whole night is gone. Carbon Panel treats your worlds the way production teams treat state: isolated, observable, and recoverable.

Other tools

Hand-rolled scripts and bare JVM processes on a shared host.

  • Shared environments can make failures harder to isolate
  • Port-forwarding a new server means editing firewall rules
  • Backups are a cron job nobody has ever restored from
  • Idle servers burn RAM all night, every night

Carbon

Every server is a Docker container with real limits, routes and history.

  • Each server runs in an isolated container
  • New server = new hostname, routed automatically
  • World-aware backups with retention and offsite copies
  • Stop idle server processes and wake on connection

A control plane, not a start button.

From container orchestration to modpack distribution, Carbon Panel ships the whole toolchain — opinionated where it matters, self-hosted everywhere.

Docker-native server management

Deploy vanilla, Paper, Purpur, Fabric, Quilt, Forge, NeoForge and Bedrock in seconds — each in its own container with CPU and RAM limits, automatic Java selection, and Aikar-tuned JVM presets.

One panel. Every machine.

Carbon Panel runs Minecraft servers wherever you have machines — the PC in your room, a box in the closet, a VPS in the cloud — and manages them as one fleet behind one address.

  1. Players get one address.

    survival.yourdomain.com is all they ever type — one DNS record and one port, no juggling.

  2. The proxy routes every connection.

    The handshake names the destination, so each player lands in the right container on the right machine.

  3. Servers run where you have machines.

    Keep the always-on survival at home and burst event servers into the cloud — or the other way around.

  4. One control plane keeps it in sync.

    Routes, consoles and a typed API work identically across every machine — one panel, one view.

  5. Let idle servers rest.

    Stop idle server processes and wake them when players connect. The panel, proxy and host continue to use their own resources.

Good to know.

Is Carbon Panel really free?
Yes. It's open source under the MPL-2.0 license — free to use, modify and self-host. There are no paid tiers, no seats, and no cloud account required.
Where are my worlds and data stored?
In plain directories and Docker volumes on your own storage — including an SQLite control database and per-server data volumes. Review configured integrations and offsite backups to understand where data is sent.
Which server types and loaders are supported?
Vanilla, Paper, Purpur, Spigot, Bukkit, Fabric, Quilt, Forge, NeoForge, Folia and Pufferfish for Java Edition, plus Bedrock support through built-in Geyser/Floodgate modules. Java runtimes (8, 11, 17, 21+) are selected automatically.
Do I need to port-forward every server?
No. Carbon Panel's built-in proxy multiplexes traffic through a single port (25565) and routes players by hostname — so survival.yourdomain.com and creative.yourdomain.com can reach different containers with one DNS setup.
Can I run it alongside other Docker workloads?
Yes. Carbon Panel orchestrates its own isolated server containers and can manage remote Docker nodes too. Each server runs in a container; review ports, storage and resource limits for your environment.
How do I get started?
Clone the repository and run it with Docker Compose, or build from source with Go and Bun. The getting-started guide walks through Docker Compose, Proxmox LXC, prebuilt binaries and source builds.
